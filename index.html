How it works

Four steps.
Zero exposure.

Every position is encrypted end-to-end using Zama's FHEVM. No plaintext amounts ever touch the chain.

01
🔐

Encrypt

Your deposit amount is encrypted client-side using FHE before it leaves your browser. The ciphertext is the only thing sent onchain.

02
🏦

Deposit

Deposit cWETH as encrypted collateral. The contract stores an encrypted handle — no plaintext amount is ever written to storage.

03
💸

Borrow

Borrow against your collateral. The LTV check runs entirely in FHE — the result is an encrypted boolean. No bot can read it.

04
🔓

Decrypt

Only you can decrypt your balance. Sign a message with your wallet — the backend verifies ownership and returns your plaintext balance.

Privacy model

What bots see.
What they don't.

Liquidation bots need collateral value, debt value, and health factor to operate. VEIL encrypts all three.

⚠ Exposed on Aave / Compound

Everything is public

Any bot can read your position onchain and calculate your exact liquidation price in real time.

  • Collateral amount — visible
  • Debt amount — visible
  • Health factor — calculable
  • Liquidation price — calculable
  • Position size — visible
✓ Hidden on VEIL

Everything is encrypted

Bots see only a boolean — this address has a position. Nothing else. Health factor computation runs in FHE onchain.

  • Collateral amount — encrypted
  • Debt amount — encrypted
  • Health factor — FHE ebool, never revealed
  • Liquidation price — unknowable
  • Position size — encrypted
// What a liquidation bot sees on Aave

// What a liquidation bot sees on VEIL
const collateral = getCollateral(address); // → encrypted bytes
const debt = getDebt(address); // → encrypted bytes
const health = collateral × price / debt × price; // → ??? × price = ???
// Bot gives up. Can't compute. Can't liquidate.
